Nexo Management

An operations ERP for small distributors, connecting suppliers, purchasing, warehouses, customers, sales and inventory movements.

Operations ERPPurchasing + stock + salesInteractive demo

Problem

In a distribution business, orders, goods and warehouses easily become disconnected. It gets hard to tell what arrived, where it is and what still needs picking for each customer.

Solution

A connected flow: purchase order, warehouse receiving, stock by location, customer order and dispatch. The API uses FastAPI and MongoDB, and the interface uses React.

Result

Purchases and sales update stock at the right step, transfers move quantities between warehouses, and movements stay linked to their order and counterparty. The dashboard flags low-stock items.

Try the flow: receive a purchase, transfer stock and dispatch an orderOpen full screen

This is the React app from the App-Controle-de-Estoque repository. In this demo, the API runs in the browser and records stay in this device's local storage.

How it works

  1. Supplierstarts a purchase
  2. Receivingupdates the selected warehouse
  3. Inventoryis tracked by warehouse
  4. Customer orderchecks availability at dispatch
  5. Youtrack the shipment and what needs restocking

What you can try

  • Purchasing and receivinglinked to a supplier and destination warehouse.
  • Sales and dispatchlinked to a customer, with a stock availability check.
  • Stock by warehouseand transfers that preserve the global balance.
  • Operations dashboardwith inventory value, alerts and recent movements.
  • No-server demo: records stay in this browser's local storage.

WhatsApp automations

The two flows that weigh most on a local business: qualifying whoever messages on WhatsApp, and reminding whoever generated a PIX payment and did not pay.

AutomationPython, no dependenciestests passing

Problem

A real-estate agent reads chat after chat to find out who is ready to buy. A shop loses sales because nobody reminds the customer about the pending payment.

Solution

Qualifier: four questions, a scoring rule and a HOT, WARM or COLD summary for the agent. Recovery: after the waiting time it checks the payment and only sends a reminder if it is still pending.

Result

Tested logic, ready to plug in. The integration points (official WhatsApp API and payment status) are isolated in one function each, so adapting it for a client touches a single place.

How the payment recovery works

  1. Checkoutthe customer generates a PIX
  2. Wait10 minutes (configurable)
  3. Checkthe payment status
  4. Decidepending gets a reminder, paid stays silent
  5. Customergets the right link at the right time

Try it both ways

  • Original script: in the Lab, the published Python runs in your browser and shows the real output.
  • Visual: in the home page simulation, each step lights up as the chat happens.
  • Bug fixed: a lead answering “just looking for now” (in Portuguese) was scored HOT. Any variation of “just looking” now counts as a weak signal, with a test for it.

Technologies

  • Python
  • dataclasses
  • unittest
  • WhatsApp Cloud API (integration point)

Connecting to the official WhatsApp API requires the client's Meta Business account, so real sending is set up in each client's project.
